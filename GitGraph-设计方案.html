GitGraph · 设计方案

1. 项目概述

GitGraph 是一个 VS Code 桌面版插件，以图形化提交历史（Commit Graph）为核心，提供对 Git 仓库的可视化浏览与日常操作能力。布局与交互参考 SourceTree：左侧为仓库/分支/远程/标签树，中部为提交图列表，底部为选中提交的详情面板（完整提交信息、变更文件、差异）。

1.1 目标

  • 看得清：以彩色拓扑图直观呈现分支、合并、标签与 HEAD 位置；一行提交展示图形、提交说明、作者、时间、短 SHA。
  • 查得快：点击提交行即可查看完整 SHA、完整提交注释（含正文）、变更文件列表；支持打开文件、在系统文件管理器中定位；文本文件可查看任意版本间差异。
  • 用得顺：GUI 完成 Fetch / Pull / Push / 重置到某次提交 / 切换分支等日常 Git 操作，带进度、取消与清晰错误反馈。
  • 扛得住：针对大仓库（数万至十万级提交）做分页加载、虚拟滚动与分层渲染，保证流畅。

1.2 非目标（本期明确不做）

  • 不嵌入 Git 实现（不使用 libgit2/dugite），完全调用系统 git CLI。
  • 不做 SourceTree 式的"仓库书签管理器"（管理任意磁盘路径仓库列表）；本期仓库来源 = 当前工作区的全部 Git 仓库（多根工作区支持）。
  • 不支持 VS Code Web（vscode.dev / github.dev）：Web 环境无法执行本地 git 命令。
  • 交互式 rebase、cherry-pick、stash、子模块等高级操作列入 P2 路线（见 2.1）。

2. 需求分析

2.1 功能需求清单（FR）

优先级定义：P0 首个可用版本必须交付；P1 紧随其后的增强；P2 远期路线。

编号功能描述优先级
FR-01打开提交图视图（编辑器标签页形式）；多仓库工作区下可通过侧栏/下拉切换仓库P0
FR-02提交图渲染：图形列以彩色线条与节点表达分支/合并拓扑（支持交叉、八爪合并、多根仓库）P0
FR-03提交列表列：图形 | 提交说明 | 作者 | 短 SHA | 时间（相对时间/绝对时间可切换）P0
FR-04Ref 徽标：HEAD→分支、本地分支、远程分支、Tag，以彩色 chip 显示在对应提交行P0
FR-05点击提交行 → 底部详情面板：完整 SHA（可复制）、作者/提交者及邮箱、作者时间/提交时间、完整 Commit Comment（标题+正文）、变更文件列表（状态 A/M/D/R、±行数、路径）P0
FR-06文件级操作：打开工作区文件、以只读方式打开某历史版本、在系统文件管理器中显示（Reveal）、复制路径P0
FR-07文本差异：面板内联 diff 快速预览 + 双击/按钮打开 VS Code 内置差异编辑器（支持任意两版本、commit vs 工作区）P0
FR-08Fetch：工具栏按钮（fetch --all --prune，可配置）+ 侧栏远程节点右键按远程 fetch；进度显示、可取消P0
FR-09Pull：merge / rebase / ff-only 三种策略可选（默认取自设置），进度显示、可取消P0
FR-10Push：无上游时引导设置上游（-u）；进度显示、可取消P0
FR-11重置仓库到某次提交：soft / mixed / hard 三种模式选择 + 模式说明；hard 需二次确认并提示将丢弃的变更P0
FR-12切换分支：双击本地分支切换；点击远程分支 → 创建本地跟踪分支；提交右键 → 分离头指针检出P0
FR-13按 ref 过滤提交图：点击侧栏分支/远程分支/标签或工具栏下拉，仅显示该 ref 可达提交P0
FR-14自动刷新：监视 .git 变化（HEAD/refs/index/packed-refs）防抖刷新；工具栏手动刷新按钮P0
FR-15侧栏树：仓库区、本地分支（含 ahead/behind 徽标）、远程主机>分支、标签；各节点右键菜单P0
FR-16创建分支（自当前 HEAD 或选中提交）、删除分支（含未合并提示）P1
FR-17合并分支到当前分支（--no-ff 可选，冲突时引导处理）P1
FR-18标签管理：在选中提交上创建/删除标签（轻量/附注）P1
FR-19搜索过滤：按提交说明/作者/SHA 过滤（git log --grep / --author）P1
FR-20任意两次提交对比（选中两个提交 → 区间 diff 文件列表）P1
FR-21工作区变更/暂存与提交界面（SourceTree 的"文件状态"页签）P2
FR-22Stash 推入/弹出/列表；cherry-pick、revert、rebaseP2
FR-23子模块、图片/二进制可视化 diffP2

2.2 非功能需求（NFR）

类别指标 / 约束
首屏性能10,000 提交仓库：从打开视图到首屏（500 行）渲染完成 < 800ms（本机 git 命令耗时除外的上限另计）
滚动性能提交列表滚动保持 60fps；单帧列表工作（行回收/复用 + Canvas 重绘）< 8ms

兼容性VS Code ≥ 1.85 桌面版（Windows / macOS / Linux）；git ≥ 2.30；多根工作区；路径含中文/空格正确处理（core.quotepath=false）

可用性所有长操作（fetch/pull/push）可取消；错误信息包含 git stderr 摘要与"查看完整输出"入口；界面文案 zh-CN/en 双语
隐私不采集遥测、不访问网络（仅由 git 本身访问远端）

2.3 假设与澄清（请确认）

A1 · "Put" 理解为 "Push"。需求原文"Fetch、Pull、Put"中的 Put 判断为笔误，按 Push（推送）设计。
A2 · 仓库范围。本期仓库来源为"当前工作区的全部 Git 仓库"（含多根），侧栏仓库区切换；SourceTree 那种管理任意磁盘路径的"书签"列入 P2。
A3 · 界面语言。默认简体中文，内置 i18n 切换英文（跟随 VS Code 语言，可强制指定）。
A4 · Diff 呈现方式。以 VS Code 内置差异编辑器为主（语法高亮、性能最好），详情面板内联 diff 作为快速预览；两者并存。
A5 · 合并提交的文件列表默认按 first-parent 口径显示差异（SourceTree 同款默认），后续提供"组合 diff"选项。

3. 总体架构与技术选型

3.1 架构总览

┌───────────────────────────── VS Code 桌面版 ─────────────────────────────┐ │ Extension Host 进程（Node.js） │ │ ┌──────────────────────────────────────────────────────────────────┐ │ │ │ extension.ts 激活入口 · 命令/菜单注册 · 状态栏当前分支 │ │ │ │ git/ GitExecutor(spawn git CLI) │ │ │ │ GitService（高层 API：log/refs/fetch/…） │ │ │ │ RepoDiscovery（工作区仓库发现） │ │ │ │ RepoWatcher（fs.watch .git，防抖刷新） │ │ │ │ webview/ GraphPanel（WebviewPanel 生命周期与保留状态） │ │ │ │ MessageRouter（消息协议路由） │ │ │ │ DiffContentProvider（gitgraph: 只读文档） │ │ │ │ ops/ 操作执行器（fetch/pull/push/reset/checkout） │ │ │ │ · 每仓库串行队列 · 进度流 · 取消 │ │ │ └──────────▲──────────────────────────────────┬────────────────────┘ │ └─────────────│ postMessage(JSON, reqId 关联) │ TextDocumentContentProvider│ │ │ scheme: gitgraph: │ ┌─────────────┴──────────────────────────────────▼────────────────────┐ │ Webview（沙箱）— UI 全部在此渲染 │ │ 工具栏 · 左侧栏(分支/远程/标签树) · 提交图主区 · 详情面板/内联diff │ │ lanes.ts（lane 算法，与扩展侧共享同一份源码）· 原生 TS，零运行时依赖 │ └─────────────────────────────────────────────────────────────────────┘

数据流要点：

  • 只读数据（提交、refs）由扩展侧经 git log / for-each-ref 获取并解析为结构化对象，按页推送给 Webview；lane 拓扑计算放在 Webview 侧（纯函数 src/graph/lanes.ts，与扩展共享源码、可单测），避免扩展主机成为渲染瓶颈。
  • 操作类请求（fetch/pull/push/reset/checkout）由 Webview 发起，扩展侧按仓库串行执行，进度按行流式回推（git --progress）。
  • 差异文档通过自定义 gitgraph: 协议的 TextDocumentContentProvider 提供，直接复用 VS Code 内置差异编辑器的全部能力（虚拟滚动、语法高亮、minimap）。

3.2 技术选型

决策点选择理由（含被否方案）
语言TypeScript（strict）VS Code 生态标准；协议与模型可在两侧共享类型
Git 访问spawn 系统 git CLI功能全覆盖（reset/push 等）；否决 vscode.git 内置 API——其不暴露 reset/push 等写操作，且属非稳定内部接口；否决 dugite/nodegit——引入数十 MB 二进制、包体大、与用户已装 git 行为不一致
UI 容器WebviewPanel（编辑器标签页）SourceTree 式布局需要大画布；否决 TreeView API——无法绘制图形与自由布局
前端框架无框架，原生 TS + 手写组件核心性能件（虚拟滚动、Canvas）本就必须手写；零依赖使包体小、内存低、冷启动快；CSS 手写并消费 VS Code 主题 CSS 变量
图形绘制Canvas 2D（线条层）+ DOM（行）见第 5 节；否决纯 SVG——数万行时节点过多；否决整块 Canvas——文本列要原生可选中/无障碍
打包esbuild（扩展与 Webview 各一个 bundle）秒级增量构建；产物小
测试vitest（单测）+ @vscode/test-electron（集成）lanes 算法/解析器为纯函数，快速回归；集成测试用脚本生成的夹具仓库

3.3 进程模型与生命周期

  • 插件在 gitgraph.open 命令首次执行时激活（lazy activation）。
  • GraphPanel 被 dispose 时：停止 watcher、终止进行中的 git 子进程（若用户无前台操作则挂后台继续可选，默认终止）；再次打开时从扩展侧缓存的 RepoState 快照恢复，避免重复加载。
  • Webview 隐藏不销毁（VS Code 默认可回收 DOM）：设置 retainContextWhenHidden: false 以省内存，恢复时由扩展重发 repoState 全量状态重建 UI（状态的唯一事实来源在扩展侧）。

4.1 布局映射与整体结构

4.3 顶部工具栏（规格）

元素行为

4.2 左侧边栏（规格）

  • 仓库区：工作区内全部仓库列表，当前项高亮；显示当前分支名。
  • 分支：本地分支；当前分支前有圆点标记；有上游时显示 ↓n ↑m 徽标（来自 rev-list 计数）；单击 = 过滤图至该分支，双击 = 切换检出（FR-12），右键 = 菜单（检出 / 拉取 / 推送 / 合并到当前分支 P1 / 删除 P1 / 复制名称）。
  • 远程：按 remote 分组（origin 等）→ 远程分支；单击过滤；右键 = 检出为新的本地分支 / fetch 此远程 / prune；远程主机组右键 = fetch --all。
  • 标签：单击过滤；右键 = 删除 P1 / 复制名称。
  • 分支/标签数量 > 500 时侧栏列表启用虚拟滚动（与主区同机制）。

4.5 详情面板（规格）

  • 位置：默认底部（SourceTree 同款），设置可改右侧；高度可拖拽（140–60% 视高）、双击分隔条折叠/展开。

  • 合并提交：文件列表口径 = first-parent diff（假设 A5），提供"切换为组合差异"P1。

5. 提交图渲染引擎

5.1 数据获取与解析

分页策略：首屏加载 pageSize（默认 500）条，滚动接近底部（剩余 < 2 屏）自动追加下一页；累计达到 maxAutoLoad（默认 20,000）后停止自动加载，显示"继续加载"按钮。

命令（完整参数；<repo> 由 executor 注入 -C）：

git log
  --topo-order                 # 保证子提交先于父提交出现（lane 算法前提）
  --all                        # 含全部分支/远程/标签可达提交
  --date=iso-strict
  --pretty=format:%H%x1f%h%x1f%P%x1f%an%x1f%ae%x1f%ad%x1f%cn%x1f%ce%x1f%cd%x1f%D%x1f%s%x1f%b%x1e
  -n <pageSize> [--skip <loaded>]
  [<ref>]                      # FR-13 过滤时追加，替换 --all
  • 字段分隔符 U+001F、记录分隔符 U+001E，杜绝与提交信息内容冲突；解析在 分片 中进行（每片 ≤ 2000 条，requestAnimationFrame/微任务间隔），避免长任务阻塞扩展主机。
  • %D（decoration）就地解析出 chips：按逗号切分，识别 HEAD -> branch、tag: vX、origin/xxx（远程）与本地分支名；与 for-each-ref 结果互相校验补充（如 HEAD 分离时 %D 仅含 HEAD）。
  • --skip 在超大仓库会退化为 O(skip+n) 遍历：文档 FAQ 引导用户运行 git commit-graph write --reachable 加速；这也是 maxAutoLoad 上限存在的原因。
  • refs 全量：见 6.4 for-each-ref；提交计数（ahead/behind、可选的分支提交数）：git rev-list --left-right --count upstream...HEAD。

5.2 Lane 分配算法

输入为 topo 序提交数组（子在前）。核心思想：维护一组"活跃 lane"，每条 lane 记录其期待的下一个提交 id（即该支线将流向的父提交）。

type LaneCell = string | null          // lane 期待的下一个提交 id
lanes: LaneCell[] = []
segments: Segment[] = []               // 每行边界的连线段（供 Canvas 绘制）

for (const c of commits) {             // topo 序，子在前
  // 1) 本提交被哪些 lane 期待（同父多子 = 交叉/criss-cross）
  const hit = indicesOf(lanes, c.sha)
  let lane: number
  if (hit.length > 0) {
    lane = Math.min(...hit)            // 取最左命中 lane 作为本提交位置
    for (const k of hit) if (k !== lane) {
      segments.push({ row: c.row, from: k, to: lane, kind: 'merge-in' }) // 收敛弧线
      lanes[k] = null                  // 多余 lane 让位
    }
  } else {
    lane = firstEmpty(lanes)           // 复用空位，否则 append
  }
  c.lane = lane

  // 2) 安排父提交去向
  if (c.parents.length === 0) {        // 根提交：支线终止
    lanes[lane] = null
  } else {
    lanes[lane] = c.parents[0]         // 第一父延续本 lane（主干直线）
    for (const p of c.parents.slice(1)) {   // 其余父 = merge 来源，分配新 lane
      const existing = lanes.indexOf(p)     // 父已被其他 lane 期待 → 复用（criss-cross）
      if (existing >= 0) {
        segments.push({ row: c.row, from: lane, to: existing, kind: 'merge-out' })
      } else {
        const k = firstEmpty(lanes)
        lanes[k] = p
        segments.push({ row: c.row, from: lane, to: k, kind: 'fork' })
      }
    }
  }
}
  • 正确性：topo 序保证处理某提交时其所有子提交已处理，因此"期待命中"只可能出现在当前行；算法天然覆盖 criss-cross、octopus merge、多根仓库。
  • 增量：追加新一页时 lanes 状态即上一页末尾状态，只需处理新提交（O(新增)），不重算历史；但为控制 lane 漂移，追加后对全空尾部 lane 做压缩重排（仅影响视觉，不影响正确性）。
  • 颜色：lane 取色 = 调色盘 laneColor(lane)；若某 lane 起点对应具名分支头，则该 lane 使用分支语义色（绿/紫），直至收敛。
  • 纯函数无副作用 → vitest 直接用生成夹具断言（见 13.2 用例矩阵）。

5.3 虚拟滚动与 Canvas 分层

  • 行 DOM：容器 overflow-y:auto；内部撑高元素 height = N * ROW_H；可见行 = first = floor(scrollTop / ROW_H) 至 last = ceil((scrollTop + viewportH) / ROW_H)，上下各多渲染 10 行缓冲；行元素池化复用（< 60 个节点常驻），仅更新文本与 class，不做 innerHTML 重建。
  • Canvas 线条层：绝对定位在图形列区域，高度 = 视口高（非全列表高！）；滚动时按 translateY(-scrollTop) 重绘可见行范围 [first-1, last+1] 的 segments；尺寸按 devicePixelRatio 缩放，避免模糊。
  • 坐标：x(lane) = PADDING + lane * LANE_W（LANE_W=14，PADDING=10）；行内纵向 y：上行中心 rowTop + ROW_H/2。曲线用三次贝塞尔短半径圆角：横向换轨在半个行高内完成，控制点纵向偏移 k = ROW_H/4（默认 6px），即 C(x1,y)(x1,y+k)(x2,y2-k)(x2,y2)；纵向主干保持长直线段——走线紧凑工整（类电路走线观感），相邻 lane 换轨不产生大弧度摆动。
  • 滚动同步：Canvas 重绘与行复用同帧完成（scroll 事件 → rAF 合并）；实测目标单帧 < 8ms。
  • chip 仍用 DOM（可点击、可悬浮），叠加于 Canvas 之上，随行复用。

5.5 增量加载与刷新

  • 追加：新页解析完成 → 计算增量 lanes → commitsAppend 消息 → 列表仅追加行池登记与撑高元素高度更新；Canvas 下一帧重绘。
  • refs 变化（fetch/checkout/外部命令）：重建 RepoState 但保留滚动位置与选中提交（选中提交消失时回退到最近仍存在的祖先）；提交数组做 key（SHA）级 diff，仅变更行更新。
  • HEAD 变化：不重载提交数据，仅更新 chips 与选中标记（快路径）。
  • diff 缓存：详情文件列表与内联 diff 按 sha:path LRU（100 项）缓存；refs 刷新时按受影响 ref 失效。

6. Git 集成层

6.1 命令执行器（GitExecutor）

// 所有命令的公共形态
spawn(gitPath, [
  '-C', repoRoot,
  '-c', 'core.quotepath=false',        // 中文文件名不转义（关键）
  '-c', 'core.preloadIndex=true',
  '--no-optional-locks',               // 只读命令不抢 index 锁（关键）
  ...args
], {
  env: process.env,                    // 继承 VS Code 注入的 askpass/凭据变量（见 6.2）
  windowsHide: true
})
  • 参数一律数组传递，不经 shell 拼接 —— 天然免疫注入与空格/中文路径问题。
  • 编码：stdout/stderr 以 UTF-8 解码（StringDecoder 处理跨 chunk 多字节截断）；git 侧已用 quotepath=false + 输出本身为 UTF-8。
  • 分类：只读命令（log/for-each-ref/show/diff/status）默认 30s 超时、输出上限 8MB（超出截断并标记）；网络命令（fetch/pull/push）无超时、流式读取 --progress 行、可取消（kill 子进程 + SIGTERM）。
  • 并发：同一仓库只读并发上限 4；写操作按仓库串行（内存队列），避免 index.lock 冲突。
  • git 探测：解析顺序 = 设置 gitgraph.gitPath → vscode.git 扩展 API 的 git.path → PATH 中的 git；启动时执行 git --version 校验，失败进入 4.8 错误态。
  • 错误模型：{ code: 'E_GIT_EXIT', exitCode, command, stderrTail } 等（错误码表见第 8.4 节），供 UI 统一呈现。

6.2 认证（HTTPS/SSH）

  • 扩展宿主进程环境已含 VS Code 内置 Git 注入的凭据代理变量（VSCODE_GIT_ASKPASS_MAIN / VSCODE_GIT_ASKPASS_NODE / GIT_ASKPASS）。子进程完整继承 process.env，因此 HTTPS 凭据（含 GitHub 账号授权）与内置 Git 体验一致，无需自建凭据管理。
  • SSH：依赖用户本机 ssh-agent / ~/.ssh；若 git 因等待 passphrase 卡住（无 askpass 可用），检测 60s 无输出且无进度 → 提示"认证可能需要交互，是否在集成终端中重试？"，降级方案：将同一命令在集成终端（window.createTerminal）中执行，用户可在终端完成交互认证。

6.3 仓库发现与监视

  • 发现：工作区根逐个 git rev-parse --show-toplevel；命中即注册；多根全部纳入侧栏。根目录非仓库时显示占位（不递归扫描，避免性能陷阱；P2 提供"选择文件夹添加"）。
  • 监视：fs.watch(<root>/.git, {recursive: true})（Windows/macOS 原生支持；Linux 降级为监听显式清单：HEAD、index、packed-refs、refs/、MERGE_HEAD、CHERRY_PICK_HEAD）；忽略 objects/、logs/、COMMIT_EDITMSG 等噪声。
  • 防抖：250ms 合并触发 → 重建 RepoState（走 5.5 快路径）；fetch/pull/push/reset 完成后主动触发一次刷新，不等 watcher。

6.5 危险操作防护

  • Reset 对话框：三选一（保留工作区 soft / 保留索引 mixed / 丢弃全部变更 hard）+ 各模式一句话说明（本地化）；选择 hard 时：先 status --porcelain 统计，脏则列出"将丢弃 n 个文件的未提交修改"，要求点击红色确认按钮（无"回车确认"，防误触）；hard 仅在用户明确选择时执行，插件永不默认 hard。
  • Checkout 预检：脏工作区时先提示"有 n 个未提交修改"，提供【继续尝试】（git 自身会拒绝有冲突的切换并保护数据）/【取消】；不隐式执行 stash。
  • 写操作互斥：同仓库串行队列；进行中时工具栏按钮禁用并显示队列状态。
  • 路径安全：所有 openFile / reveal 请求先 path.resolve 并校验以仓库根为前缀（见 12 节），拒绝越界。

9. 数据模型（TypeScript，两侧共享）

// common/models.ts
interface RepoMeta { id: string; name: string; root: string; headBranch?: string }

interface GitActor { name: string; email: string; date: string /* iso-strict */ }

interface RefChip { name: string; kind: 'head' | 'remote' | 'tag'; isHead?: boolean }

interface Commit {
  sha: string; shortSha: string;
  parents: string[];                 // 空数组 = 根提交
  author: GitActor; committer: GitActor;
  subject: string; body: string;
  refs: RefChip[];                   // %D 解析结果
  lane: number;                      // webview 侧 lanes.ts 填充
  row: number;
}

interface BranchInfo {
  name: string; fullName: string; sha: string;
  upstream?: string;                 // origin/main
  ahead?: number; behind?: number;   // rev-list 计数
  isHead: boolean; subject?: string; lastAuthor?: string; lastDate?: string;
}

interface RepoState {
  repoId: string;
  head: { sha: string; branch?: string; detached: boolean };
  branches: BranchInfo[]; remotes: { name: string; branches: BranchInfo[] }[];
  tags: { name: string; sha: string; date: string }[];
  status: { dirtyCount: number };
  filterRef: string | null;          // FR-13
  commits: Commit[];                 // 当前已加载页
  commitsLoaded: number; hasMore: boolean;
  stateVersion: number;              // 局部刷新对账用
}

interface FileChange {
  path: string; oldPath?: string;    // R 状态
  status: 'A' | 'M' | 'D' | 'R' | 'C' | 'T';
  additions?: number; deletions?: number;   // 二进制为 undefined
}

interface CommitDetail extends Commit { files: FileChange[]; filesTruncated: boolean }

interface DiffLine { kind: 'ctx' | 'add' | 'del'; oldNo?: number; newNo?: number; text: string }
interface DiffHunk { header: string; oldStart: number; newStart: number; lines: DiffLine[] }
interface UnifiedDiff { path: string; hunks: DiffHunk[]; truncated: boolean }

11. 国际化

  • 运行时文案：键值表 i18n/zh-cn.ts、i18n/en.ts，接口 t(key, params)；语言解析：设置 gitgraph.language = auto 时跟随 vscode.env.language。

  • 时间/数字本地化：Intl.DateTimeFormat / NumberFormat；相对时间自实现（"3 分钟前"），避免引入库。

12. 安全设计

  • CSP（Webview HTML 头）：default-src 'none'; img-src ${cspSource} data:; font-src ${cspSource}; style-src ${cspSource} 'unsafe-inline'; script-src 'nonce-${nonce}'。无任何外网资源。
  • XSS 防线（提交信息/作者名/分支名/文件路径均按不可信数据处理）：UI 层唯一文本出口为 setText(el, text)（走 textContent）与 escapeHtml（仅拼 HTML 模板处）；code review 检查项单列。
  • 消息守卫：两侧 handler 以类型守卫逐字段校验（protocol.ts 提供 isXxxMsg()），非法消息丢弃计数，超阈值输出日志。
  • 路径越界：openFile / reveal / diff 的 path 一律 resolve 后校验 startsWith(repoRoot + sep)；SHA/ref 校验 /^[0-9a-f]{7,40}$/、refs/ 合法字符集。
  • 无遥测、无外联：除 git 自身访问远端外，插件不发起网络请求。

16. 风险与对策

风险对策
SSH passphrase 等交互认证无法在子进程完成60s 无进度检测 + 一键降级到集成终端执行同命令（6.2）
超大仓库 --skip 翻页变慢maxAutoLoad 上限 + 手动续载；FAQ 引导 commit-graph 加速；P2 研究 commit-graph 遍历优化
watcher 在 Linux 上事件粒度粗/丢失显式清单监听 + 操作后主动刷新兜底 + 手动刷新按钮
Webview 被回收导致状态丢失状态唯一事实来源在扩展侧，恢复时重发全量 repoState（3.3）
市场名称冲突（已有 "Git Graph"）上架前查重，必要时更名（如 GitGraph Plus / GitGraphite），代码侧无影响
并发 git 调用造成 index.lock 冲突--no-optional-locks + 每仓库读写队列（6.1）
内置 git 扩展 askpass 变量在未来版本变动启动时探测变量存在性；缺失时回退终端方案并提示

17.3 术语
