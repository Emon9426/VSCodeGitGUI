1. 背景与目标

当前 GitBoard 所有操作都在一个 Workspace 下，缺少随手记录的入口：想记几行字，却要纠结存到哪个工程、什么格式。本功能在插件内新增「快速笔记」页，特点：

诉求设计回应需求编号
不想选保存位置默认保存到工程外的固定笔记目录（可改），新建即写盘，零对话框R2
完整富文本标题/字号字体/表格（合并+嵌套）/背景色卡片/代码块/行内代码/画图区/三种列表/AI 编辑/分割线，/ 呼出菜单R4–R10
快、不依赖 Git独立模块零 Git 引用、独立 webview bundle、懒加载；Git 崩溃不影响R11–R12
带走与复用导出 MD / HTML / PDF、另存为任意文件夹；HTML 保存完整数据可再次打开继续编辑R13–R15
管理多条笔记三栏布局：左文件列表（图标/列表双视图）、中编辑器、右大纲R16
定位一句话
Obsidian 的「本地文件、秒开、数据归我」 × Confluence 的「富文本表达力（表格/彩色卡片）」 × Notion 的「/ 命令交互」——但长在 VS Code 里，给开发者用。

2. 市面产品调研与借鉴

产品核心形态对我们的借鉴不照搬的原因
Obsidian本地 Markdown 文件库 + 双链 + Canvas①本地纯文件存储，数据归用户、秒开；②左侧文件列表 + 右侧大纲的三栏信息架构；③文件名即标题以 MD 为源导致表格合并/彩色卡片/画图等富文本表达能力受限（MD 无此语义）
Notion云端块式编辑 + 数据库①「/」呼出块菜单的交互范式；②块级拖拽与选中浮动工具栏云端慢、强登录，违背「快速、本地」定位
Confluence企业 Wiki 富文本①预制彩色背景卡片（信息/成功/警告/危险）的表达方式；②强大的表格（合并单元格）；③页面树过重，非个人快速记录场景
Typora所见即所得 MD 编辑器①所见即所得（无预览分栏）的编辑体验；②导出 PDF/HTML 的心智MD 源文件限制同上
语雀云端知识库①「画板」作为可嵌入内容块（不是独立页面）；②大纲联动高亮云端、企业向
flomo / OneNote轻量速记①「新建即写、零对话框」的速记心智；②默认落固定位置富文本能力弱（无表格合并/画图）
VS Code 笔记插件
（Markdown Notes / Foam 等）		MD 文件 + 编辑器联动反衬空白：VS Code 内几乎没有「所见即所得富文本 + 本地秒开」的笔记方案（均为 MD 路线）——
调研结论
①存储走本地文件（数据归属、可同步、可备份）；②编辑体验走所见即所得富文本而非 MD 源码；③「/」菜单 + 选中浮动工具栏成为标配交互；④彩色卡片、表格合并是差异化表达力（Confluence 系）；⑤画图做成内容块（语雀式）而非独立画布应用，保证流程图嵌在笔记上下文里。

3. 编辑器内核选型（含画图方案）

3.1 富文本内核对比

内核架构 / 框架耦合表格合并嵌套结构HTML 往返结论
TipTap
(ProseMirror)		headless，原生 TS 可用（无 React 依赖）；扩展生态最大✅ 官方 Table 扩展（mergeCells / splitCell）✅ ProseMirror schema 原生支持任意块嵌套✅ 内置 DOMParser/序列化，保真度高✅ 选定
Lexical
(Meta)		React 生态为主，vanilla 接入成本高△ 社区扩展✅△ 需自写备选否决
Slate强绑 React，本项目零 React△ 自写✅△否决（框架冲突）
Quill 2vanilla 友好❌ 弱（无原生合并）❌ 有限△ 有损否决（表格硬伤）
Editor.js块式 JSON△ 社区△△否决（块式心智不符）
Milkdown
(ProseMirror)		MD 优先的 PM 封装✅✅△ MD 中转有损否决（同 TipTap 底座但绕道 MD）

选定：TipTap（开源核心，MIT）。理由：①与本项目 vanilla TS webview 零冲突；②表格合并/嵌套、TaskList、代码高亮、Highlight/颜色、Placeholder 全部有官方开源扩展；③HTML 序列化内置 → 导出/再导入保真是天然能力（正好满足 R14 的 HTML 往返）；④文档与社区最成熟。所依赖扩展均为开源 npm 包（@tiptap/core、starter-kit、extension-table 等），不引入其付费云服务。

3.2 画图方案

方案体积能力结论
Excalidraw 嵌入>1MB，强依赖 React最全否决：体积与框架冲突，违背快速打开
mermaid 渲染~700KB文本→图（非自由绘制）否决：需求是「画」不是「写代码生成」
自研轻量 SVG 画板
(TipTap NodeView)		~30–40KB（自研）基础图形 + 箭头连线 + 文字 = 流程图✅ 选定

画板能力定稿（够画流程图即可，不做全能绘图）：矩形/圆角矩形、菱形（判断）、椭圆、直线、箭头连线（自动吸附图形锚点）、文本标签、选中/拖拽移动/删除、缩放画布适配内容宽。数据存为画板节点内的 JSON，渲染为内联 SVG（导出 HTML 直接内联，导出 MD 见降级表）。

4. 需求规格 R1–R16

编号需求规格与验收标准
R1入口与直达活动栏新增「快速笔记」图标（与 GitBoard 图标并列）；单击直达笔记页（WebviewPanel 标签页）；另有命令 gitboard.notes（命令面板）与快捷键 Ctrl+Alt+N。无任何中间面板。
R2默认目录（工程外）默认 ~/GitBoardNotes/（Windows 即 %USERPROFILE%\GitBoardNotes），首次打开自动创建；globalState 记忆 gitboard.notesDir，可在页内「更改目录」。新建笔记零对话框直接落盘。
R3新建/命名新建笔记默认名「未命名笔记」，文件名自动 slug + 去重（未命名笔记.gbnote.json、-2 递增）；标题自动跟随正文首行 Heading（文件重命名 = 列表重命名）。
R4文本与排版多级标题 H1–H4；正文；字体（默认/宋体/黑体/楷体/等宽 + 自定义输入）与字号（12–32px 预设 + 自定义）；加粗/斜体/下划线/删除线/行内代码/文字颜色/高亮色；有序/无序/待办列表（待办 Ctrl+Enter 切换勾选）；引用块；分割线。
R5表格插入 N×M 表格（默认 3×3）；行列增删；表头行/列开关；合并单元格（多选后合并/拆分，colspan+rowspan）；嵌套表格（单元格内可再插表格/列表/卡片，schema 层支持）；列宽拖拽。
R6背景色卡片Confluence 式预制卡片 5 种：信息(蓝)/成功(绿)/警告(黄)/危险(红)/笔记(灰)，各带可选标题栏与图标；卡片内是完整富文本容器（可放任意块）。
R7代码块围栏代码块 + 语言下拉（高亮渲染，低配 light/highlight.js 子集）；复制按钮；Tab 缩进。
R8画图区域见 3.2：内嵌 SVG 画板块，双击进入编辑，点击外部退出；画板占位高度自适应。
R9「/」命令菜单行首输入 / 呼出（也支持工具栏按钮）；支持中文/英文关键字过滤；分组展示（结构/内容/媒体）；↑↓ 选择 Enter 确认 Esc 关闭。菜单项 = 4 标题/3 列表/表格/代码块/行内代码/5 卡片/画板/分割线/引用/时间戳。
R10AI 编辑复用现有 Copilot 通路（vscode.lm，零凭证，与提交信息 AI 同开关 gitboard.ai.enabled）。选中文字 → 浮动「AI」按钮或 Ctrl+Alt+A：续写/润色/翻译(中↔EN)/摘要/自定义指令；结果以差异预览呈现（接受替换/插入/放弃）。无可用模型时入口隐藏。
R11性能：秒开笔记页冷启动到可编辑 ≤ 300ms（本地目录、≤100 笔记规模）；打开不触碰任何 Git 探测。
R12Git 崩溃隔离notes 模块零 git import（CI 断言：notes bundle 不含 executor/service 引用）；GitBoard 主面板异常/未打开均不影响笔记页；笔记页异常不影响主面板（独立错误边界）。
R13自动保存输入防抖 800ms 自动保存 + 失焦/切换/关闭强制保存；标题栏保存状态指示（●未保存/✓已保存/时间）；Ctrl+S 手动保存。
R14导出 HTML（往返）自包含单文件 .html：内联样式 + 内嵌完整文档 JSON（<script type="application/json">）。浏览器双击打开=纯阅读（数据块被浏览器忽略）；在插件内「打开」该 html → 检测到数据块 → 格式与内容完全还原且可继续编辑。再次保存回写 html 同格式。
R15导出 MD / PDF / 另存为MD：按降级表转换（见 §7），画图导出为同名 .svg 文件引用；PDF：优先本机 Edge/Chrome headless 静默导出（矢量、中文友好），失败回退「用系统浏览器打开 HTML 手动打印」；另存为：把当前笔记（原生格式或所选导出格式）保存到指定文件夹。
R16三栏布局左：文件列表（图标网格 / 列表双视图切换、按修改时间倒序、关键字过滤、新建/重命名/删除/在资源管理器中显示）；中：编辑器；右：大纲（H1–H4 树、点击滚动定位、光标所在章节自动高亮、可折叠）。三栏宽度可拖拽并记忆；可分别折叠。

6. 技术架构

6.1 模块与隔离（对应 R11/R12）

src/
├─ notes/                      ★ 新增顶层模块，禁止 import git/**
│  ├─ NotesPanel.ts            WebviewPanel 生命周期/消息路由/文件 IO 编排
│  ├─ notesStore.ts            目录管理、列表/读写/重命名/删除/搜索（fs，零 git）
│  ├─ exportMd.ts              doc→Markdown（含降级规则）
│  ├─ exportHtml.ts            doc→自包含 HTML（内嵌 JSON，往返源）
│  └─ pdf.ts                   Edge/Chrome headless 探测与静默导出
├─ ui/notes/                   ★ 独立 webview bundle（out/notes.js，esbuild 第二入口）
│  ├─ main.ts                  三栏装配/状态机
│  ├─ editor/                  TipTap 装配 + 自定义扩展（卡片/画板/时间戳）
│  ├─ sketch.ts                SVG 画板（NodeView）
│  └─ outline.ts / fileList.ts 大纲与文件列表
  • 懒加载：extension.ts 不在 activate 时 require notes；首次打开笔记页才 import('./notes/NotesPanel')——Git 主路径零额外开销。
  • 独立 bundle：out/notes.js 与主 webview.js 分离，TipTap 体积只进笔记页。
  • 隔离断言：单元测试扫描 notes 产物，出现 git/executor|git/service|child_process.*git 引用即失败。

6.2 存储格式（原生 .gbnote.json）

{
  "version": 1,
  "title": "会议记录",              // UI 显示名；正文首 H1 变化时自动跟随
  "created": "2026-08-30T10:00:00+08:00",
  "updated": "2026-08-30T12:30:00+08:00",
  "doc": { /* TipTap/ProseMirror 文档 JSON —— 唯一权威数据 */ }
}

选 JSON 而非 MD 作原生格式的原因：表格合并/嵌套、彩色卡片、画板在 MD 中无语义可表达（必然有损）；JSON 是编辑器无损源，导出才谈降级。文件仍是人类可读、可进 Git/同步盘。

6.3 HTML 往返机制（对应 R14）

导出 .html
  ├─ <style>    内联笔记样式（阅读态渲染，与编辑态视觉一致）
  ├─ <body>     doc → DOM（浏览器直接打开即原文，数据块被忽略）
  └─ <script type="application/json" id="gitboard-note">
       { "gitboardNote": 1, "version": 1, "doc": {...} }   ← 完整无损数据
插件内打开 .html
  └─ 检测 #gitboard-note → JSON.parse → schema 校验 → 载入编辑器（继续编辑）
       └─ 保存策略：默认回写原 .html（保持往返）；「另存为」可落 .gbnote.json

6.4 消息协议（gitboard.notes.*）

Webview → 宿主说明
notes.list / notes.read / notes.create / notes.rename / notes.delete文件 CRUD（read 返回 doc JSON）
notes.save {id, doc, title}自动/手动保存（防抖由前端发）
notes.setDir / notes.pickDir查看/更改笔记根目录
notes.export {id, doc, fmt: md|html|pdf}导出（md/html → 保存对话框；pdf → 静默管线）
notes.saveAs {id, doc, fmt}另存为指定文件夹（系统对话框选目录）
notes.revealInFM在资源管理器中显示笔记文件

宿主 → WebviewnotesList / noteContent / saved{id,at} / dirChanged / aiChunk / aiDone / aiError / notify

PDF 管线（含已知坑）

notes bundle 体积拖慢打包/加载独立懒加载入口；体积预算入 CI
